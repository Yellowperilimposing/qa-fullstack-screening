## 31. Git

> [!abstract] Коротко
> Git — система контроля версий.


**Git** — система контроля версий.

Git помогает:

* хранить историю изменений;
* работать в ветках;
* откатываться к прошлым версиям;
* объединять изменения разных разработчиков;
* отправлять код в удаленный репозиторий.

---

### 31.1. Основные команды

| Команда | Что делает |
| --- | --- |
| `git status` | Показывает состояние файлов |
| `git add` | Добавляет изменения в индекс |
| `git commit` | Создает коммит |
| `git push` | Отправляет изменения в удаленный репозиторий |
| `git pull` | Забирает изменения из удаленного репозитория |
| `git branch` | Показывает или создает ветки |
| `git switch` | Переключает ветку |
| `git checkout` | Переключает ветку или файл |
| `git merge` | Сливает ветки |
| `git rebase` | Переносит коммиты поверх другой ветки |
| `git log` | Показывает историю коммитов |

---

### 31.2. Когда начинается ревью

Обычно процесс ревью начинается после того, как разработчик:

1. Создал ветку.
2. Сделал изменения.
3. Создал коммит.
4. Запушил ветку.
5. Открыл Pull Request или Merge Request.

---

### 31.3. Merge vs rebase

`merge` объединяет две ветки и сохраняет историю ветвления. Часто создается merge commit.

`rebase` переносит коммиты текущей ветки поверх другой ветки. История становится линейной, но хэши коммитов меняются.

История коммитов в исходном виде лучше сохраняется при `merge`.

---

### 31.4. Что такое .gitignore

`.gitignore` — файл со списком того, что Git не должен отслеживать.

Примеры:

```gitignore
target/
.idea/
*.log
.env
```

---

### 31.5. Что такое конфликт

**Конфликт** — ситуация, когда Git не может сам объединить изменения.

Чаще всего конфликт появляется, когда разные люди изменили одни и те же строки.

Как исправлять:

1. Открыть конфликтный файл.
2. Выбрать нужный вариант изменений.
3. Удалить маркеры конфликта.
4. Выполнить `git add`.
5. Продолжить merge или rebase.

---

### 31.6. Что важно сказать на скрининге

Git нужен для контроля версий. Основной flow: создать ветку, сделать изменения, `git add`, `git commit`, `git push`, открыть pull request. Merge сохраняет историю ветвления, rebase делает историю линейной.
