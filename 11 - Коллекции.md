## 11. Коллекции

> [!abstract] Коротко
> Java Collections Framework — набор интерфейсов и реализаций для хранения и обработки групп объектов. `Map` входит во framework, но не наследует `Collection`.

### 11.1. Основные интерфейсы

- `List` — упорядоченная последовательность, допускает дубликаты;
- `Set` — множество уникальных элементов;
- `Queue` / `Deque` — очереди и двусторонние очереди;
- `Map` — пары ключ-значение, ключи уникальны.

Коллекции работают с объектами, поэтому для примитивов используются обёртки: `List<Integer>`, а не `List<int>`.

---

### 11.2. `List`

```java
List<String> names = new ArrayList<>();
names.add("Anna");
names.add("Ivan");
names.add("Anna");
```

`ArrayList` обычно является выбором по умолчанию для списка: быстрый доступ по индексу и эффективное добавление в конец.

`LinkedList` реализует `List` и `Deque`, но утверждение «лучше для частых вставок в середину» требует оговорки: чтобы вставить по индексу, сначала нужно пройти до нужного узла. На практике `ArrayList` часто быстрее благодаря локальности данных.

---

### 11.3. `Set`

```java
Set<String> set = new HashSet<>();
set.add("Java");
set.add("Java"); // второй такой элемент не добавится
```

- `HashSet` — порядок не гарантируется;
- `LinkedHashSet` — сохраняет порядок добавления;
- `TreeSet` — хранит элементы в порядке сортировки.

Уникальность в hash-based коллекциях определяется через `equals()` и `hashCode()`.

---

### 11.4. `Queue` и `Deque`

```java
Queue<String> queue = new ArrayDeque<>();
queue.offer("first");
queue.offer("second");

System.out.println(queue.poll()); // first
```

Для обычной очереди/стека часто предпочитают `ArrayDeque`, а не `LinkedList`.

Полезные пары методов:

| Операция | С исключением | Специальное значение |
| --- | --- | --- |
| добавить | `add()` | `offer()` |
| взять и удалить | `remove()` | `poll()` |
| посмотреть | `element()` | `peek()` |

---

### 11.5. `Map`

```java
Map<String, Integer> ages = new HashMap<>();
ages.put("Danil", 28);
Integer age = ages.get("Danil");
```

Если записать значение по существующему ключу, старое значение заменится.

- `HashMap` — порядок не гарантируется;
- `LinkedHashMap` — сохраняет порядок вставки (либо access-order при соответствующей настройке);
- `TreeMap` — сортирует по ключам.

`HashMap` допускает один `null`-ключ и `null`-значения. `TreeMap` при естественном порядке обычно не допускает `null`-ключ.

---

### 11.6. `equals()` и `hashCode()`

Для объектов, используемых в `HashMap`/`HashSet`, важно соблюдать контракт:

- если `a.equals(b)` — `true`, то `a.hashCode() == b.hashCode()` тоже должен быть `true`;
- одинаковый `hashCode()` не означает обязательное равенство объектов;
- поля, участвующие в `equals()`/`hashCode()`, нежелательно менять, пока объект используется как ключ `HashMap` или элемент `HashSet`.

---

### 11.7. Итерация и изменение коллекции

Нельзя бездумно структурно изменять обычную коллекцию внутри enhanced `for`: это может привести к `ConcurrentModificationException`.

Для удаления во время обхода можно использовать `Iterator`:

```java
Iterator<String> iterator = names.iterator();
while (iterator.hasNext()) {
    if (iterator.next().isBlank()) {
        iterator.remove();
    }
}
```

Или методы вроде `removeIf()`:

```java
names.removeIf(String::isBlank);
```

---

### 11.8. Изменяемые и неизменяемые коллекции

```java
List<String> fixed = List.of("a", "b");
```

Коллекции, созданные через `List.of`, `Set.of`, `Map.of`, нельзя структурно изменять: `add`, `remove`, `put` приведут к `UnsupportedOperationException`.

Для изменяемой копии:

```java
List<String> mutable = new ArrayList<>(fixed);
```

---

### 11.9. Короткое сравнение

| Тип | Дубликаты | Порядок | Типичный выбор |
| --- | --- | --- | --- |
| `List` | да | да | `ArrayList` |
| `Set` | нет | зависит от реализации | `HashSet` |
| `Queue/Deque` | да | порядок очереди | `ArrayDeque` |
| `Map` | ключи уникальны | зависит от реализации | `HashMap` |
