## 11. Коллекции

> [!abstract] Коротко
> Коллекции — это структуры данных для хранения группы объектов.


### 11.1. Что такое коллекции

**Коллекции** — это структуры данных для хранения группы объектов.

Главное отличие от массивов:

| Массив                            | Коллекция               |
| --------------------------------- | ----------------------- |
| Размер фиксированный              | Размер может изменяться |
| Может хранить примитивы и объекты | Хранит объекты          |
| Менее гибкий                      | Более гибкая            |
| `int[] numbers`                   | `List<Integer> numbers` |

Пример массива:

```java
int[] numbers = {1, 2, 3};
```

Пример коллекции:

```java
List<Integer> numbers = new ArrayList<>();

numbers.add(1);
numbers.add(2);
numbers.add(3);
```

---

### 11.2. Основные интерфейсы коллекций

В Java Collection Framework есть основные интерфейсы:

1. `List`;
2. `Set`;
3. `Queue`;
4. `Map`.

Важно: `Map` формально не наследуется от `Collection`, но относится к Java Collections Framework.

---

### 11.3. List

**List** — это список элементов.

Особенности:

* хранит элементы в порядке добавления;
* допускает дубликаты;
* позволяет обращаться к элементам по индексу.

Основные реализации:

* `ArrayList`;
* `LinkedList`.

Пример:

```java
import java.util.ArrayList;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<String> names = new ArrayList<>();

        names.add("Danil");
        names.add("Ivan");
        names.add("Danil");

        System.out.println(names);
    }
}
```

Результат:

```text
[Danil, Ivan, Danil]
```

---

### 11.4. Порядок и сортировка List

`List` всегда хранит элементы в определенном порядке.

По умолчанию порядок такой, в каком элементы добавили в список.

```java
List<String> names = new ArrayList<>();

names.add("Ivan");
names.add("Danil");
names.add("Anna");

System.out.println(names); // [Ivan, Danil, Anna]
```

Элементы можно получать по индексу:

```java
System.out.println(names.get(0)); // Ivan
```

Список можно отсортировать самостоятельно.

```java
Collections.sort(names);

System.out.println(names); // [Anna, Danil, Ivan]
```

Можно сортировать через comparator:

```java
names.sort(Comparator.reverseOrder());

System.out.println(names); // [Ivan, Danil, Anna]
```

Коротко: `List` упорядочен по индексу. Обычно порядок соответствует добавлению элементов, но мы можем сами отсортировать список.

---

### 11.5. ArrayList

**ArrayList** — самая популярная реализация `List`.

Подходит, когда:

* нужно часто получать элементы по индексу;
* нужно хранить обычный список;
* нужно добавлять элементы в конец списка.

Пример:

```java
List<String> cities = new ArrayList<>();

cities.add("Moscow");
cities.add("Kazan");
cities.add("Ufa");

System.out.println(cities.get(0)); // Moscow
System.out.println(cities.size()); // 3
```

Основные методы:

```java
cities.add("Samara");      // добавить элемент
cities.get(0);             // получить элемент по индексу
cities.set(1, "Sochi");    // заменить элемент
cities.remove(0);          // удалить элемент
cities.size();             // получить размер
cities.contains("Ufa");    // проверить наличие
```

---

### 11.6. LinkedList

**LinkedList** — список, где элементы связаны друг с другом ссылками.

Может использоваться как:

* список;
* очередь.

Пример:

```java
import java.util.LinkedList;
import java.util.List;

List<String> names = new LinkedList<>();

names.add("Danil");
names.add("Ivan");
names.add("Oleg");
```

На скрининге достаточно знать:

* `ArrayList` чаще используют для обычных списков;
* `LinkedList` может быть удобен, когда часто добавляют или удаляют элементы в начале или середине списка;
* на практике `ArrayList` используется гораздо чаще.

---

### 11.7. Set

**Set** — коллекция уникальных элементов.

Особенности:

* не хранит дубликаты;
* обычно не гарантирует порядок;
* используется, когда нужны только уникальные значения.

Основные реализации:

* `HashSet`;
* `LinkedHashSet`;
* `TreeSet`.

Пример:

```java
import java.util.HashSet;
import java.util.Set;

Set<String> names = new HashSet<>();

names.add("Danil");
names.add("Ivan");
names.add("Danil");

System.out.println(names);
```

В коллекции останутся только уникальные значения.

---

### 11.8. Чем List отличается от Set

| List | Set |
| --- | --- |
| Хранит элементы списком | Хранит уникальные элементы |
| Допускает дубликаты | Не допускает дубликаты |
| Есть индекс | Индекса нет |
| Порядок обычно соответствует добавлению | Порядок зависит от реализации |
| Пример: `ArrayList` | Пример: `HashSet` |

Пример:

```java
List<String> list = new ArrayList<>();
list.add("Danil");
list.add("Danil");

System.out.println(list); // [Danil, Danil]
```

```java
Set<String> set = new HashSet<>();
set.add("Danil");
set.add("Danil");

System.out.println(set); // [Danil]
```

---

### 11.9. HashSet

**HashSet** — самая популярная реализация `Set`.

Особенности:

* хранит только уникальные элементы;
* порядок элементов не гарантируется;
* работает быстро для добавления, удаления и поиска.

Пример:

```java
Set<Integer> numbers = new HashSet<>();

numbers.add(1);
numbers.add(2);
numbers.add(2);
numbers.add(3);

System.out.println(numbers);
```

---

### 11.10. LinkedHashSet

**LinkedHashSet** — это `Set`, который сохраняет порядок добавления элементов.

```java
Set<String> names = new LinkedHashSet<>();

names.add("Danil");
names.add("Ivan");
names.add("Oleg");

System.out.println(names);
```

Порядок будет таким же, как при добавлении.

---

### 11.11. TreeSet

**TreeSet** — это `Set`, который хранит элементы в отсортированном порядке.

```java
Set<Integer> numbers = new TreeSet<>();

numbers.add(5);
numbers.add(1);
numbers.add(3);

System.out.println(numbers); // [1, 3, 5]
```

---

### 11.12. Queue

**Queue** — очередь.

Обычно работает по принципу FIFO:

```text
First In — First Out
Первым пришёл — первым вышел
```

Пример из жизни: очередь в магазине.

```java
import java.util.LinkedList;
import java.util.Queue;

Queue<String> queue = new LinkedList<>();

queue.add("Первый");
queue.add("Второй");
queue.add("Третий");

System.out.println(queue.poll()); // Первый
System.out.println(queue.poll()); // Второй
```

Основные методы:

```java
queue.add("Danil");     // добавить
queue.offer("Ivan");    // добавить
queue.poll();           // получить и удалить первый элемент
queue.peek();           // посмотреть первый элемент без удаления
```

---

### 11.13. Map

**Map** — коллекция для хранения данных в формате ключ-значение.

Пример:

```text
ключ → значение
login → danil
age → 28
city → Ufa
```

Основные реализации:

* `HashMap`;
* `LinkedHashMap`;
* `TreeMap`.

Пример:

```java
import java.util.HashMap;
import java.util.Map;

Map<String, Integer> ages = new HashMap<>();

ages.put("Danil", 28);
ages.put("Ivan", 30);

System.out.println(ages.get("Danil")); // 28
```

---

### 11.14. Чем Map отличается от других коллекций

`Map` отличается тем, что хранит не одиночные элементы, а пары **ключ-значение**.

```text
ключ -> значение
email -> user@mail.com
id -> 123
```

Главное отличие:

* `List`, `Set`, `Queue` хранят элементы;
* `Map` хранит пары ключ-значение;
* у `Map` ключи уникальны;
* значение достают по ключу через `get(key)`.

```java
Map<String, Integer> ages = new HashMap<>();

ages.put("Danil", 28);

Integer age = ages.get("Danil");
```

---

### 11.15. Что может быть ключом в Map

Ключом в `Map` может быть почти любой объект:

* `String`;
* `Integer`;
* `Long`;
* enum;
* пользовательский класс.

Пример:

```java
Map<String, Integer> ages = new HashMap<>();
Map<Long, String> users = new HashMap<>();
Map<User, List<Order>> ordersByUser = new HashMap<>();
```

Важно: если объект используется как ключ, у него должны быть корректно реализованы `equals()` и `hashCode()`. Иначе `HashMap` может плохо находить значения.

Плохо использовать в качестве ключа изменяемый объект, если поля, участвующие в `equals()` и `hashCode()`, могут поменяться после добавления в map.

---

### 11.16. Может ли null быть ключом в Map

Зависит от реализации `Map`.

| Реализация | Может ли `null` быть ключом |
| --- | --- |
| `HashMap` | Да, один `null` ключ |
| `LinkedHashMap` | Да, один `null` ключ |
| `TreeMap` | Обычно нет, будет ошибка при естественной сортировке |
| `Hashtable` | Нет |

Пример с `HashMap`:

```java
Map<String, Integer> map = new HashMap<>();

map.put(null, 100);

System.out.println(map.get(null)); // 100
```

Коротко: в `HashMap` `null` может быть ключом, но ключ `null` может быть только один, потому что ключи в `Map` уникальны.

---

### 11.17. HashMap

**HashMap** — самая популярная реализация `Map`.

Особенности:

* хранит пары ключ-значение;
* ключи уникальны;
* порядок не гарантируется;
* быстро ищет значение по ключу.

Пример:

```java
Map<String, String> users = new HashMap<>();

users.put("login1", "Danil");
users.put("login2", "Ivan");

System.out.println(users.get("login1")); // Danil
```

Если добавить значение с уже существующим ключом, старое значение заменится:

```java
users.put("login1", "Oleg");

System.out.println(users.get("login1")); // Oleg
```

---

### 11.18. LinkedHashMap

**LinkedHashMap** сохраняет порядок добавления ключей.

```java
Map<String, Integer> map = new LinkedHashMap<>();

map.put("first", 1);
map.put("second", 2);
map.put("third", 3);
```

---

### 11.19. TreeMap

**TreeMap** хранит ключи в отсортированном порядке.

```java
Map<Integer, String> map = new TreeMap<>();

map.put(3, "three");
map.put(1, "one");
map.put(2, "two");

System.out.println(map);
```

Результат:

```text
{1=one, 2=two, 3=three}
```

---

### 11.20. Краткое сравнение коллекций

| Интерфейс | Что хранит          | Дубликаты       | Порядок   | Пример реализации |
| --------- | ------------------- | --------------- | --------- | ----------------- |
| `List`    | список              | Да              | Да        | `ArrayList`       |
| `Set`     | уникальные элементы | Нет             | Не всегда | `HashSet`         |
| `Queue`   | очередь             | Да              | Да        | `LinkedList`      |
| `Map`     | ключ-значение       | Ключи уникальны | Не всегда | `HashMap`         |
