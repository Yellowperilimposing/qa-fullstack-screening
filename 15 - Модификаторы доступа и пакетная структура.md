## 15. Модификаторы доступа и пакетная структура

> [!abstract] Коротко
> Модификаторы доступа определяют видимость классов и членов класса. Для членов используются `public`, `protected`, package-private и `private`.

### 15.1. Таблица доступа для членов класса

| Модификатор | Тот же класс | Тот же пакет | Наследник в другом пакете | Посторонний класс в другом пакете |
| --- | --- | --- | --- | --- |
| `private` | да | нет | нет | нет |
| package-private | да | да | нет | нет |
| `protected` | да | да | да* | нет |
| `public` | да | да | да | да |

`package-private` — это отсутствие явного модификатора; отдельного ключевого слова `default` для доступа нет.

`protected` имеет важный нюанс: в другом пакете доступ наследнику предоставляется в контексте наследования, а не как общий доступ к любому объекту родительского типа.

---

### 15.2. `public`

```java
public class User {
    public void login() {}
}
```

Член доступен из любого кода, которому доступен сам класс.

Для top-level класса допустимы `public` или package-private. Top-level класс нельзя объявить `private` или `protected`.

---

### 15.3. `private`

```java
class User {
    private String password;
}
```

`private` скрывает член внутри объявляющего класса. Это базовый инструмент инкапсуляции.

---

### 15.4. Package-private

```java
class UserService {
    void validate() {}
}
```

Такой класс/метод виден только внутри того же пакета.

---

### 15.5. `protected`

```java
public class Animal {
    protected String name;
}
```

- в том же пакете `protected` доступен почти как package-private;
- в другом пакете доступ есть у наследника через наследуемый член.

Для скрининга полезно помнить: `protected` — это не просто «private для наследников», потому что классы того же пакета тоже имеют доступ.

---

### 15.6. Пакеты

```java
package ru.company.project.users;
```

Пакеты:

- группируют типы;
- предотвращают конфликты полных имён;
- участвуют в управлении доступом.

По соглашению имена пакетов пишут строчными буквами и часто строят от обратного доменного имени.

---

### 15.7. Импорты

```java
import java.util.List;
import java.util.ArrayList;
```

`import` не «подключает библиотеку» во время выполнения — он позволяет использовать короткое имя типа в исходном коде.

`java.lang` импортируется неявно. Типы из того же пакета тоже не требуют `import`.

```java
import java.util.*;
```

Wildcard импортирует типы конкретного пакета, но не его подпакеты.

---

### 15.8. Практика

- Поля обычно делают `private`.
- Публичным оставляют минимально необходимый API.
- Package-private полезен для деталей реализации внутри пакета.
- `protected` применяют осознанно, когда наследнику действительно нужен доступ.
