## 8. Исключения

> [!abstract] Коротко
> Исключение — объект, который описывает ненормальную ситуацию во время выполнения программы и может быть выброшен и обработан.

### 8.1. Иерархия

Базовый тип — `Throwable`. Основные ветки:

- `Error` — серьёзные проблемы JVM/среды, которые приложение обычно не пытается обрабатывать;
- `Exception` — исключительные ситуации, которые приложение может обрабатывать.

`RuntimeException` и его наследники относятся к unchecked exceptions.

---

### 8.2. Частые исключения

| Исключение | Когда возникает |
| --- | --- |
| `NullPointerException` | обращение через `null` |
| `ArrayIndexOutOfBoundsException` | неверный индекс массива |
| `ArithmeticException` | например, целочисленное деление на ноль |
| `NumberFormatException` | строка не может быть преобразована в число |
| `IllegalArgumentException` | аргумент метода недопустим |
| `IOException` | ошибка ввода-вывода |

---

### 8.3. `try-catch-finally`

```java
try {
    int result = 10 / 0;
} catch (ArithmeticException e) {
    System.out.println("Деление на ноль");
} finally {
    System.out.println("Завершение блока");
}
```

`catch` обрабатывает подходящее исключение. Можно иметь несколько `catch`; более конкретные типы должны идти раньше общих.

`finally` обычно выполняется независимо от того, возникло исключение или нет. Формулировка «выполняется всегда» слишком абсолютна: например, принудительное завершение JVM может не дать ему выполниться.

---

### 8.4. Checked и unchecked

**Checked exceptions** — наследники `Exception`, кроме `RuntimeException`. Компилятор требует их либо обработать, либо объявить через `throws`.

```java
void read() throws IOException {
    // ...
}
```

**Unchecked exceptions** — `RuntimeException` и его наследники. Компилятор не требует явной обработки:

```text
NullPointerException
IllegalArgumentException
NumberFormatException
```

Обычно они сигнализируют об ошибках в данных, состоянии или логике программы.

---

### 8.5. `throw` и `throws`

`throw` непосредственно выбрасывает объект исключения:

```java
if (age < 0) {
    throw new IllegalArgumentException("age must be >= 0");
}
```

`throws` в сигнатуре сообщает, какие checked exceptions метод может передать вызывающему коду:

```java
void loadFile() throws IOException {
    // ...
}
```

---

### 8.6. Try-with-resources

Для ресурсов, реализующих `AutoCloseable`, предпочтительнее try-with-resources: ресурс закрывается автоматически.

```java
try (FileInputStream input = new FileInputStream("notes.txt")) {
    int firstByte = input.read();
} catch (IOException e) {
    System.out.println(e.getMessage());
}
```

Это обычно безопаснее ручного закрытия ресурса в `finally`.

---

### 8.7. Практические правила

- Лови наиболее конкретный тип исключения, который реально можешь обработать.
- Не используй `catch (Exception e)` без причины только ради того, чтобы «не упало».
- Не проглатывай исключение пустым `catch`.
- Для некорректных аргументов метода часто подходит `IllegalArgumentException`.
- Для ресурсов предпочитай try-with-resources.
