## 35. Ответы на вопросы для собеседования

> [!abstract] Коротко
> Основные принципы ООП:


### 35.1. Какие принципы ООП знаешь?

Основные принципы ООП:

1. **Инкапсуляция** — скрываем внутреннее состояние объекта и даем доступ через методы.
2. **Наследование** — один класс может наследовать поля и методы другого класса.
3. **Полиморфизм** — один интерфейс или родительский тип может иметь разные реализации.
4. **Абстракция** — выделяем главное поведение и скрываем детали реализации.

---

### 35.2. Что такое интерфейс?

**Интерфейс** — это контракт, который описывает, что класс должен уметь делать.

В интерфейсе обычно объявляют методы без реализации, а класс, который реализует интерфейс, обязан написать реализацию этих методов.

```java
public interface Animal {
    void voice();
}
```

```java
public class Cat implements Animal {
    public void voice() {
        System.out.println("Meow");
    }
}
```

---

### 35.3. Отличие абстрактного класса от интерфейса

| Абстрактный класс | Интерфейс |
| --- | --- |
| Используется через `extends` | Используется через `implements` |
| Можно наследоваться только от одного класса | Можно реализовать несколько интерфейсов |
| Может хранить состояние через поля | Обычно описывает поведение |
| Может иметь конструктор | Конструктора нет |
| Подходит для общей базовой логики | Подходит для контракта поведения |

Коротко: абстрактный класс — это базовый класс с общей логикой, интерфейс — это контракт.

### 35.4. Что такое массивы?

**Массив** — структура данных, которая хранит несколько значений одного типа под одним именем.

```java
int[] numbers = {1, 2, 3};
```

У элементов массива есть индексы. Индексация начинается с `0`.

```java
System.out.println(numbers[0]); // 1
```

---

### 35.5. Можем ли мы увеличить массив?

Нет, размер обычного массива в Java изменить нельзя.

Если нужен больший массив, можно:

* создать новый массив большего размера и скопировать элементы;
* использовать коллекцию `ArrayList`, которая умеет динамически расти.

```java
List<Integer> numbers = new ArrayList<>();
numbers.add(1);
numbers.add(2);
```

---

### 35.6. Циклы. Что это такое и для чего используются? Что такое инкремент?

**Цикл** — конструкция, которая повторяет код несколько раз.

Циклы используют, чтобы:

* пройти по массиву;
* пройти по коллекции;
* повторять действие, пока условие истинно;
* выполнять однотипные операции.

Основные циклы:

* `for`;
* `for-each`;
* `while`;
* `do-while`.

**Инкремент** — увеличение значения на 1.

```java
i++;
```

### 35.7. Java Stream API — что это такое и для чего используется?

**Stream API** — инструмент Java для обработки коллекций в функциональном стиле.

Stream API используют, чтобы:

* фильтровать данные;
* преобразовывать данные;
* сортировать;
* собирать результат в список;
* искать элементы.

Пример:

```java
List<String> names = List.of("Danil", "Anna", "Ivan");

List<String> result = names.stream()
        .filter(name -> name.startsWith("A"))
        .toList();
```

### 35.8. Какие виды условий существуют?

В Java основные условные конструкции:

* `if`;
* `if-else`;
* `else-if`;
* `switch`;
* тернарный оператор `?:`.

Пример:

```java
if (age >= 18) {
    System.out.println("Можно");
} else {
    System.out.println("Нельзя");
}
```

### 35.9. Что такое коллекции и мапы?

**Коллекции** — структуры данных для хранения групп объектов.

Основные коллекции:

* `List` — список, допускает дубликаты;
* `Set` — множество, хранит уникальные элементы;
* `Queue` — очередь.

**Map** — структура данных, которая хранит пары ключ-значение.

```java
Map<String, Integer> ages = new HashMap<>();
ages.put("Danil", 28);
```

---

### 35.10. Как достать значение из мапы?

Значение из `Map` достают по ключу через метод `get`.

```java
Map<String, Integer> ages = new HashMap<>();
ages.put("Danil", 28);

Integer age = ages.get("Danil");
```

Если ключа нет, `get` вернет `null`.

Можно использовать `getOrDefault`:

```java
Integer age = ages.getOrDefault("Anna", 0);
```

### 35.11. Что такое Rest Assured?

**Rest Assured** — Java-библиотека для тестирования REST API.

Она позволяет:

* отправлять HTTP-запросы;
* передавать headers, query params, body;
* проверять status code;
* проверять тело ответа;
* доставать данные из JSON.

---

### 35.12. Расскажи про настройку вызовов в Rest Assured

В Rest Assured часто настраивают:

* `baseURI`;
* `basePath`;
* headers;
* content type;
* авторизацию;
* логирование запросов и ответов.

Пример:

```java
RestAssured.baseURI = "https://api.example.com";
RestAssured.basePath = "/api/v1";
```

```java
given()
        .header("Authorization", "Bearer token")
        .contentType(ContentType.JSON)
        .body(requestBody)
.when()
        .post("/users")
.then()
        .statusCode(201);
```

---

### 35.13. Rest Assured: структура запросов

Типичная структура Rest Assured:

```java
given()
        .header("Authorization", "Bearer token")
        .queryParam("page", 1)
        .body(requestBody)
.when()
        .post("/users")
.then()
        .statusCode(201)
        .body("name", equalTo("Danil"));
```

Блоки:

* `given()` — подготовка запроса;
* `when()` — выполнение запроса;
* `then()` — проверка ответа.

### 35.14. Что такое session key и для чего он используется?

**Session key** — ключ или идентификатор сессии пользователя.

Он нужен, чтобы сервер понимал, что несколько запросов относятся к одному пользователю или одной авторизованной сессии.

Обычно session key передают:

* в cookie;
* в header;
* как token.

### 35.15. Что такое аннотация и для чего она используется?

**Аннотация** — специальная метка в коде, которая добавляет метаинформацию.

Аннотации используются, чтобы:

* помечать тестовые методы;
* настраивать поведение фреймворков;
* генерировать код;
* задавать правила выполнения.

Пример:

```java
@Test
void shouldLogin() {
}
```

* `@Test`;

* `@AfterAll`;

Lombok:

### 35.17. Как выполняется аннотация BeforeAll?

`@BeforeAll` выполняется один раз перед всеми тестами в тестовом классе.

Ее используют для общей подготовки:

* поднять тестовые данные;
* настроить клиент;
* открыть общее соединение;
* выполнить дорогую подготовку один раз.

В JUnit 5 метод с `@BeforeAll` обычно должен быть `static`, если не используется `@TestInstance`.

### 35.18. Git: известные команды. После чего начинается процесс ревью?

Частые команды Git:

* `git status` — посмотреть состояние файлов;
* `git add` — добавить изменения в индекс;
* `git commit` — создать коммит;
* `git push` — отправить изменения в удаленный репозиторий;
* `git pull` — забрать изменения;
* `git checkout` / `git switch` — переключиться на ветку;
* `git branch` — работа с ветками;
* `git merge` — слить ветки;
* `git rebase` — перенести коммиты поверх другой ветки;
* `git log` — посмотреть историю.

Процесс ревью обычно начинается после того, как разработчик запушил ветку и создал pull request / merge request.

---

### 35.19. Merge и rebase: в чем разница? При какой операции сохраняется история коммитов?

`merge` объединяет две ветки и создает merge commit. История сохраняется такой, какой была, видно, где ветки объединились.

`rebase` переносит коммиты текущей ветки поверх другой ветки. История становится линейной, но хэши коммитов меняются.

История коммитов в исходном виде лучше сохраняется при `merge`.

### 35.20. Для чего используется gitignore?

`.gitignore` нужен, чтобы Git не отслеживал лишние файлы.

Например:

* временные файлы;

Пример:


### 35.21. Что такое конфликт? Из-за чего он появляется? Как подойти к исправлению?

**Конфликт** — ситуация, когда Git не может автоматически объединить изменения.

Обычно конфликт появляется, если два человека изменили одни и те же строки в одном файле.

Как исправлять:

1. Открыть файл с конфликтом.
2. Найти конфликтные блоки.
3. Выбрать нужный вариант или объединить оба.
4. Удалить служебные маркеры Git.
5. Выполнить `git add`.
6. Завершить merge или rebase.

### 35.22. JUnit 5: что такое лямбда-выражения?

**Лямбда-выражение** — короткая форма записи функции.

Пример:

```java
() -> service.call()
```

В JUnit 5 лямбды часто используются в assertions:

```java
assertThrows(IllegalArgumentException.class, () -> {
    service.createUser(null);
});
```

### 35.23. JUnit 5: что такое расширения и для чего они используются?

**Extensions** в JUnit 5 — механизм расширения поведения тестов.

Расширения позволяют:

* выполнять код до или после теста;
* управлять тестовыми ресурсами;
* внедрять параметры;
* подключать кастомную логику;
* интегрировать JUnit с другими инструментами.

Подключаются через `@ExtendWith`.

```java
@ExtendWith(MyExtension.class)
class MyTest {
}
```

### 35.24. Как работает сборщик проекта?

Сборщик проекта, например Maven или Gradle:

1. Читает конфигурационный файл проекта.
2. Скачивает зависимости.
3. Компилирует код.

### 35.25. В чем принцип наследования в ООП?

**Наследование** позволяет одному классу получить поля и методы другого класса.

Родительский класс описывает общее поведение, дочерний класс может его расширить или переопределить.

```java
class Animal {
    void eat() {
        System.out.println("eat");
    }
}

class Cat extends Animal {
    void meow() {
        System.out.println("meow");
    }
}
```

### 35.26. Что такое jOOQ и для чего он используется?

**jOOQ** — Java-библиотека для работы с SQL в типобезопасном стиле.

jOOQ позволяет писать SQL-запросы через Java DSL:

```java
dsl.selectFrom(USERS)
        .where(USERS.ID.eq(1))
        .fetchOne();
```

Используется, чтобы:

* писать SQL в Java-коде;
* получать типобезопасные запросы;
* удобно маппить результат из базы;
* переиспользовать сгенерированные таблицы и поля.

---

### 35.27. Как переиспользовать полученные через jOOQ данные?

Данные, полученные через jOOQ, можно:

* сохранить в переменную;
* преобразовать в DTO;
* передать в тест;
* использовать в assertions;
* использовать для подготовки следующих запросов.

Пример:

```java
UserRecord user = dsl.selectFrom(USERS)
        .where(USERS.EMAIL.eq("test@mail.com"))
        .fetchOne();

assertThat(user.getName()).isEqualTo("Danil");
```

### 35.28. Что такое CI/CD? Что внутри файла?

**CI/CD** — практика автоматической сборки, тестирования и доставки проекта.

CI — Continuous Integration: код автоматически собирается и тестируется.

CD — Continuous Delivery / Deployment: проект автоматически доставляется или деплоится.

В CI/CD-файле обычно описано:

* когда запускать pipeline;
* какие stages есть;
* какие команды выполнять;
* какие переменные окружения использовать;
* какие артефакты сохранять;
* какие тесты запускать.

Например: build, test, deploy.

### 35.33. Чем отличается оператор `==` от метода `equals()`?

Для примитивов `==` сравнивает значения.

Для ссылочных типов `==` сравнивает ссылки, то есть один и тот же это объект или нет.

`equals()` обычно сравнивает содержимое объекта.

Для строк:

```java
String a = new String("test");
String b = new String("test");

System.out.println(a == b);      // false
System.out.println(a.equals(b)); // true
```

### 35.34. Что знаешь про исключения?

**Исключение** — ошибка во время выполнения программы.

Исключения бывают:

* checked — нужно обработать или пробросить;
* unchecked — наследуются от `RuntimeException`.

Обработка:

```java
try {
    int result = 10 / 0;
} catch (ArithmeticException e) {
    System.out.println("Ошибка");
} finally {
    System.out.println("Выполнится всегда");
}
```
