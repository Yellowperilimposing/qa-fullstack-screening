## 26. Аннотации в Java

> [!abstract] Коротко
> Аннотация — специальная метка в коде, которая добавляет метаинформацию для компилятора, фреймворка или runtime-логики.


**Аннотация** — специальная метка в коде, которая добавляет метаинформацию для компилятора, фреймворка или runtime-логики.

Аннотации не выполняют бизнес-логику сами по себе. Они подсказывают инструментам, как работать с классом, методом, полем или параметром.

---

### 26.1. Для чего используются аннотации

Аннотации используют, чтобы:

* помечать тесты;
* управлять жизненным циклом тестов;
* генерировать код;
* настраивать сериализацию;
* подключать расширения;
* описывать шаги и метаданные отчетов;
* передавать настройки фреймворкам.

---

### 26.2. Примеры аннотаций

JUnit:

```java
@Test
void shouldLogin() {
}
```

Lombok:

```java
@Getter
@Setter
public class User {
    private String name;
}
```

Allure:

```java
@Step("Login as {username}")
public void login(String username) {
}
```

---

### 26.3. Основные JUnit-аннотации

| Аннотация | Для чего нужна |
| --- | --- |
| `@Test` | Помечает метод как тест |
| `@BeforeEach` | Выполняется перед каждым тестом |
| `@AfterEach` | Выполняется после каждого теста |
| `@BeforeAll` | Выполняется один раз перед всеми тестами |
| `@AfterAll` | Выполняется один раз после всех тестов |
| `@DisplayName` | Задает читаемое имя теста |
| `@Disabled` | Отключает тест |
| `@ParameterizedTest` | Помечает параметризованный тест |

---

### 26.4. Что важно сказать на скрининге

Аннотация — это метка над кодом, которую читают компилятор или фреймворки. Например, JUnit через `@Test` понимает, что метод нужно запустить как тест, а Lombok через `@Getter` генерирует getter.
